# Elite Dashboard deployment guide

This document is intentionally written for a one-pass rollout after the release candidate is approved. Do not use these commands while development is still in progress.

## Preconditions

- Target release branch or commit has green GitHub Actions (`quality` and `mcp-contract`).
- VPS repository is `~/apps/youtube-creator-agent`.
- Windows repository is `C:\Users\silva\OneDrive\Desktop\Agente_YouTube_Elite`.
- Server secrets remain only in local files such as `config/server.env`, `config/keycloak.env`, and `config/tunnel.env`.
- Desktop account files remain local, including OAuth tokens and AI/UI preference files.
- Never run `git add .`, `git clean`, or `git reset --hard` as part of the rollout.

## VPS rollout

Run from the VPS repository:

```bash
cd ~/apps/youtube-creator-agent
git status --short
git fetch origin
git switch main
git pull --ff-only origin main
docker compose -f deploy/docker-compose.oracle.yml up -d --build
docker compose -f deploy/docker-compose.oracle.yml ps
```

Expected production checks:

```bash
curl -sS -o /dev/null -w "%{http_code}\n" https://mcp.silvadigitaltech.com/mcp
curl -sS -o /dev/null -w "%{http_code}\n" https://creator.silvadigitaltech.com/health
curl -sS -o /dev/null -w "%{http_code}\n" https://creator.silvadigitaltech.com/ready
```

Expected codes:

- MCP unauthenticated probe: `401`
- `/health`: `200`
- `/ready`: `200`

Then open the secure onboarding link generated by the Creator Agent, connect YouTube if necessary, and enter `/dashboard`.

## Windows notebook rollout

Run only from the existing local repository:

```powershell
Set-Location 'C:\Users\silva\OneDrive\Desktop\Agente_YouTube_Elite'
git status --short
git fetch origin
git switch main
git pull --ff-only origin main
```

Do not delete or commit the local configuration files. The desktop application remains available and the web dashboard is an additional cloud surface.

If the Python virtual environment is used locally:

```powershell
.\.venv\Scripts\Activate.ps1
python -m compileall -q src
python -m pytest -q
```

## Post-deploy acceptance checklist

1. Production health/readiness probes return the expected status codes.
2. Onboarding session opens and the connected YouTube account is detected.
3. Dashboard loads on notebook and mobile without horizontal overflow.
4. All six sections open: overview, videos, strategy, audit, publish, settings.
5. All five themes can be selected and persist after refresh.
6. Recent videos load with thumbnail and metrics.
7. Metadata preview shows a diff without writing to YouTube.
8. Cancelling a metadata preview makes no channel change.
9. Keyword validation and evidence views load with authenticated real data.
10. Upload flow can reach its final confirmation screen without publishing.
11. No real metadata update or video publication is performed during smoke testing unless explicitly approved by the owner.

## Rollback strategy

If the new cloud containers fail health/readiness checks, do not improvise with destructive Git commands. Identify the previously deployed commit from Git history, switch the VPS working tree to an approved branch/commit using a controlled fast-forward or explicit release branch, rebuild the same Compose stack, and re-run the health/readiness probes.
